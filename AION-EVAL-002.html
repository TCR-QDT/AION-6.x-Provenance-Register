Protocolo de Avaliação Multicamada

Status: Frozen 1.0.0

Implementação técnica: IA Curadora

Data: 17 de agosto de 2026

1. Objetivo

Estabelecer protocolo normativo para avaliação de respostas do sistema AION com avaliação multicamada — cada camada do pipeline (retrieval, contexto, proveniência, resposta) é avaliada individualmente, e a avaliação final não pode ser compensada por falhas em camadas críticas.

2. Camadas do Pipeline Avaliadas

PERGUNTA → formulação da consulta
RETRIEVAL → quais chunks foram recuperados do vector store
CONTEXTO → o conjunto de chunks efetivamente passado ao LLM
RESPOSTA → texto gerado pelo LLM com base no contexto
AVALIAÇÃO → aplicação das 10 categorias abaixo

3. Categorias de Avaliação (10 categorias multicamada)

CódigoCamadaO que medeCritério de PASS
R1 Retrieval Retrieval correto — chunks recuperados contêm a informação correta Chunk correto (definido no gabarito) está entre os top-K recuperados
R2 Retrieval Retrieval suficiente — contexto contém informação suficiente para responder A informação necessária está presente no contexto, mesmo que em chunk diferente do esperado
P1 Proveniência Proveniência correta — resposta cita o documento certo Documento citado na resposta corresponde ao documento do gabarito
P2 Proveniência Proveniência granular — resposta cita seção/página/chunk específico Citação inclui referência granular (página, seção, ou chunk_id)
T1 Temporalidade Coerência temporal — resposta distingue versões temporais Resposta distingue entre datas/versões diferentes e não mistura estados de épocas distintas
E1 Epistemologia Distinção evidência/interpretação — resposta marca [E]/[I]/[H] Resposta distingue afirmações textuais de inferências
N1 Negativa Tratamento correto de ausência — sistema declara "não encontrado" quando apropriado Quando a informação não está no corpus, sistema diz "INFORMAÇÃO NÃO ENCONTRADA" em vez de inferir
C1 Contradição Detecção de contradição entre documentos Quando há contradição no corpus, sistema identifica com citação dupla
S1 Síntese Qualidade da síntese histórica — reconstrução sem misturar versões Resposta distingue versões sem combinar estados incompatíveis
H1 Honestidade Honestidade epistemológica — sistema não disfarça incerteza Resposta marca UNKNOWN quando data não pode ser estabelecida; não artificialmente data

4. Regra de Não-Compensação (Crítica)

REGRA FUNDAMENTAL: Uma resposta semanticamente correta não pode compensar retrieval incorreto quando a pergunta exige proveniência.

Isto significa:

  • Se a pergunta exige proveniência (P1 ou P2) e o retrieval falhou (R1 = FAIL), a avaliação final é FAIL mesmo que a resposta seja semanticamente correta.
  • Se a pergunta exige temporalidade (T1) e o sistema recuperou chunks de versão errada, a avaliação final é FAIL.
  • Honestidade epistemológica (H1) é pré-requisito: sem H1, nenhuma outra categoria pode ser PASS.

As categorias têm dependências:

  • H1 é pré-requisito de todas
  • R1 é pré-requisito de P1, P2, T1
  • R2 é pré-requisito de C1, S1
  • N1 é independente (pode PASS mesmo com R1 FAIL, se a resposta correta for "não encontrado")

6. Avaliação Final

A avaliação final de um teste é calculada considerando:

  1. H1 deve ser PASS ou PASS-SEMANTIC (pré-requisito)
  2. Para perguntas que exigem proveniência: R1 AND P1 devem ser PASS
  3. Para perguntas que exigem temporalidade: R1 AND T1 devem ser PASS
  4. Para perguntas sobre ausência: N1 deve ser PASS (independente de R1)
  5. Para perguntas de síntese: S1 AND R2 devem ser PASS

Status final:

  • PASS — todos os critérios aplicáveis atendidos
  • PARTIAL — alguns critérios não críticos falharam
  • FAIL — critério crítico (H1, R1 para perguntas com proveniência/temporalidade) falhou
  • FAIL-LEXICAL-ONLY — apenas falhas léxicas, semanticamente correto

7. Proveniência da Avaliação

Cada avaliação registra:

  • test_id: identificador do teste (ex: B1, B2, HIST-001)
  • pergunta: texto original
  • resposta: texto gerado
  • retrieved_chunks: lista de chunks recuperados (top-K)
  • contexto_passado_ao_llm: chunks efetivamente usados
  • categoria_status: dict {R1: PASS/FAIL/..., R2: ..., ..., H1: ...}
  • avaliacao_final: PASS / PARTIAL / FAIL / FAIL-LEXICAL-ONLY
  • justificativa: explicação da decisão
  • avaliador: Humano ou IA
  • timestamp: data ISO
